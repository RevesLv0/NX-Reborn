## Findings and limits

- [AF/lens](../analysis/architecture/AF_LENS_RUN010.md): app callback argument →
  public ioctl 0x13 → internal 0x1050007 → capture's single listener; original
  relocation tables connect category-0x82 lens messages to two-word callbacks
  and the UI idle queue. CAF/AF-lock command encodings are concrete. The app's
  null removal request follows a path that leaves the listener unchanged.
  AF completion tests stored count/length 1 while a result setter copies 12
  bytes; buffer allocation and protocol meaning remain separate questions.
- [Transfer outcomes](../analysis/architecture/TRANSFER_STATE_RUN010.md): the
  response parser produces subcodes 2502/2503 from `Sub-ErrorCode`. Worker
  outcomes map specific storage-space/unsupported-file diagnostics and generic
  failure into API and APP events. A concrete singleton/vtable binding closes
  the APP dispatch target. The selected smartphone type-0x13 handler is empty;
  client-state writers, remote persistence and active delivery remain unproven.
- [Kernel TSU and sensor](../analysis/architecture/KERNEL_TSU_RUN010.md): original
  driver/attribute bindings lead to CPU/ISP upper register bytes minus 21; the
  combined formatter explicitly labels the same integers `degC`. Separate CMOS
  scaling and userspace square-root conversion are reproduced without assigning
  unverified electrical units or sensor calibration. Original branches show
  local unlock/close omissions on TSU-open failures, positive-one kernel copy
  failure and caller sign-only read checks. These are conditional static paths,
  not observed camera failures.

The [independent TSU review](../analysis/architecture/KERNEL_TSU_REVIEW_RUN010.md)
