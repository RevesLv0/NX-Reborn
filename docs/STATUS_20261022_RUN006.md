# NX500 v1.12 research status — RUN006

2026-10-22 KST. Offline research on the existing PR #1 branch. No camera access,
target executable execution, firmware installation or merge occurred.

RUN006 extends the storage-error and callback investigation and connects the
RTOS readiness packet to the packaged Linux parser. It also follows the Wi-Fi
URL notification into the actual string builder and records selected smartphone
state predicates. Independent RUN006 semantic review is **incomplete**: all four
resumed sub-agents returned an actual usage-limit error. The primary agent
continued source checks, bounded interpretation, additional Ghidra queries,
reproduction and integration; those checks are not a substitute for a separate
independent reviewer.

## Results and evidence

- [Storage errors and cancellation](../analysis/architecture/STORAGE_ERRORS_RUN006.md):
  cancellation can return 1 without file completion; the reviewed worker callback
  does not transport its write result. Conditional capture sync and chunk-loop
  sync are now enumerated alongside separate playback sync. Queue/accounting
  limits and external event uncertainty remain explicit.
- [App/network consumers](../analysis/architecture/APP_ERROR_CONSUMERS_RUN006.md):
  raw camera ID `0x3a` maps to the explicit skip-write accounting entrance. The
  gated Wi-Fi callback ignores converted storage status and reaches an unchecked
  URL state update. The freshly selected URL builder uses IP, card state and path
  strings; this is not file or remote-delivery acknowledgement. BT and smartphone
  state consumers retain separate unresolved boundaries.
- [RTOS/Linux transport](../analysis/architecture/RTOS_TRANSPORT_RUN006.md):
  concrete observer registration, thunk, frame construction, ring publication and
  signal binding. The packaged kernel consumes a four-byte prefix then overwrites
  the same destination with ten bytes. Userspace preserves that origin and maps
  category `0x82` to the notify handler; halfword `0x020a` and zero payload length
  correspond to the separately reviewed next-shot-ready parser.

## Validation and review limits

Original-byte verification covers **165 code windows in five evidence files**,
plus jump tables, vtable/GOT data and selected relocations. RTOS reproduction is
byte-for-byte identical; storage reproduction is also identical. Original ELF,
whole BIN, RTOS section and decoded-kernel hashes were checked. The RTOS extractor
additionally validates every packaged section hash. Frame arithmetic matches
the manually inspected prefix/pointer chain; this is not code emulation or a
packet capture.

During primary review, a Broadcast literal pool had been decoded as instructions
by an unfinished app extractor. The window now stops before that pool. Neighboring
function/cleanup instructions were removed from two other function-labelled
windows. New ranges follow recovered instruction gaps. The default frame
constructor `0x5c14` is distinguished from the integer constructor `0x5e50`.

Host validation: **64 tests passed**, compileall passed and whitespace checks
passed. An initial test invocation omitted the saved Python dependency directory
and failed on missing pyelftools; the corrected `PYTHONPATH=.work/python`
invocation passed all 64 tests. Both logs remain in the private run archive.

Independent semantic review must still cover the final kernel/userspace chain,
new URL/helper paths, asynchronous storage sources and queue ownership. Active
kernel/boot role, multicore visibility, callback ordering, double accounting,
dynamic symbol replacement, real transfer acknowledgement and filesystem/medium
persistence remain unobserved. The source opt xattr discrepancy and inherited
outer ZIP hash limitations from earlier runs remain unchanged.
