# 환경·저장소 변경 기록 — 2026-10-21

## 이번에 적용한 내용

- 공식 Ghidra 12.1.4를 `.work/tools/`에 설치하고 GitHub 릴리스에 게시된 SHA-256과 대조했다.
- 기존 Java는 실행 환경만 있어, Eclipse Temurin 전체 JDK 21.0.12.1+1을 별도로 설치하고 공식 체크섬과 대조했다.
- Python 분석 패키지 pyelftools 0.32·Capstone 5.0.6을 `.work/python/`에 설치했다.
- 도구 재설치·무결성 확인을 `tools/bootstrap_research.py`로 자동화했다. Linux x86_64·Python 3.12 기준이다.
- Ghidra DB는 숨김 경로 제한 때문에 `ghidra-projects/`에 두고 Git 추적에서 제외했다.
- 전체 파일 범위표, ELF 의존성 인덱스, Ghidra headless 실행·증거 내보내기·출력 무결성 검증 도구를 추가했다.
- GitHub Actions에 분석 도구 테스트를 추가했다. 펌웨어를 다운로드하거나 실행하지 않는 검사이며 작업 권한은 `contents: read`다.
- 저장소 작업 규칙과 Drive `Codex` 폴더의 실제 ID를 기록했다. 기존 `1차 시도` 자료는 참조한다.

## 네트워크·환경 설정 상태

이 채팅에서 환경 구성 자체를 편집하는 도구는 제공되지 않았다. 설치는 현재 실행 공간에서
완료했으며, 재사용 환경에 필요한 설치 절차는 위 bootstrap 파일에 저장했다.
GitHub의 분석 브랜치/PR을 기준으로 새 작업 환경을 만들 때 이 절차로 복원할 수 있다.

전체 펌웨어 ZIP은 281,999,904바이트로 Drive fetch의 256MiB 한도를 초과한다.
기존 분할본을 스트리밍하려면 `sdmntprkoreacentral.oaiusercontent.com` 접근이 필요하다.
사용자는 환경 편집 화면의 인터넷 액세스 → 추가 허용 도메인에 이 주소를 추가했다고 확인했다.
그러나 이 실행 세션의 `/etc/codex/network-policy.json`에는 해당 호스트가 없고, 실제 요청도
403으로 차단되었다. **추가 설정이 현재 세션에 적용됐다고 기록하지 않는다.**

새 실행 환경에서 먼저 해당 호스트의 정책 반영을 확인한다. Drive에서 새로운 인증된 파일
참조를 받은 뒤 스트리밍하고 파일 크기·해시를 검증한다. 만료되는 서명 URL은 Git/보고서에
저장하지 않는다. 이 세션의 `.work/`에 있는 임시 다운로드 참조도 재사용 기준이 아니다.

## 복원

1. GitHub 분석 브랜치 또는 병합된 커밋을 체크아웃한다.
2. `python tools/bootstrap_research.py --work .work`를 실행한다.
3. Drive Codex의 소스 코드/산출물 목록과 해시를 확인한다.
4. 필요한 원본 또는 Ghidra DB 스냅샷을 받아 검증 후 분석을 이어간다.

도구 설치·DB 생성과 카메라 펌웨어 설치는 별개다. 이 세션에서는 카메라 프로그램을 실행하거나
실제 카메라에 접속·설치하지 않았다.
