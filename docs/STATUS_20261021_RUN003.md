# NX500 offline reverse engineering — RUN003

2026-10-21 KST. The whole verified source corpus is now searchable by declared ELF
symbols, and the Ghidra survey has expanded from 21 to **41 distinct ELF contents**.
This is **41 / 1,895 = approximately 2.16% loaded/exported ELF coverage**, not a
whole-firmware semantic completion percentage. Non-ELF T-Kernel/boot/initializer
regions require separate analysis. No camera I/O or firmware installation occurred.

The two new automatic surveys had no analyzer timeout. All successful generations
were validated by source SHA, run identity, artifact hashes/lengths and row counts.
Followup exports do not add their discovered functions/imports again. Selected C is
inferred decompiler output, not recovered source or ABI proof.

Detailed current totals and exact generation failures are in
[`ANALYSIS_PROGRESS.md`](ANALYSIS_PROGRESS.md) and `manifests/analysis-progress.json`.
The cumulative ledger contains 46,539 mapped function locations, 183 distinct
selected functions with a completed decompilation, and 24 bounded reviewed claims
across 15 primary ELF sources. It retains earlier failures, including the JPEG
worker retries. Some reviewed systemd code was inspected directly with Capstone
without a Ghidra import; the stages are not a strict sequential completion ladder.
The matched-generation import/auto-analysis numerator is deliberately conservative:
the original 13 restored programs have current `-process -noanalysis` exports rather
than matching import-generation summaries. Their earlier documented analysis is
preserved separately; the ledger does not classify them as never analyzed.

## Important new static boundaries

1. **Boot and raw code:** code in section 1 builds a Linux command line with
   `root=/dev/mmcblk0p10` and transfers toward `0x86008000`. Section 4 contains an
   NX500 M4 initializer banner; section 5 contains T-Kernel/capture-related anchors.
   These are code/string evidence, not measurements of active processors or a
   complete flash-partition map. The shipped systemd lookup path puts explicit
   `/etc/systemd/system` units ahead of ordinary fstab-generated units under its
   traced default setup; runtime overrides and actual mounts remain unknown.
2. **Capture/IPC:** RTOS-named preferences map `/dev/mem`; one readiness-named
   consumer reads byte offset `0x1c4d`. Its producer and synchronization with SD
   completion are unknown. IPCC wrappers, driver output records and queue submission
   results have distinct meanings; no generic capture-completed flag is established.
3. **Video:** a concrete HEVC class selection, `/dev/d5_hevc` and ioctl
   `0xc10c7408` are anchored in original instructions. Generic INI mode declarations
   do not prove supported resolution/FPS or which configuration copy is active.
4. **Power:** `sysman_request_poweroff` submits `pwroff-popup` through local socket
   `/tmp/sn`. This wrapper is not proof that capture/transfer resources have stopped.
   MICOM status and body battery SOC use different device requests; units, freshness
   and shutdown thresholds remain unverified.
5. **Transfer:** the app queues start/stop requests; a lower matching-worker stop
   path sets a flag, conditionally joins and deletes the worker. The implementation
   can send either a file stream or a resized JPEG memory buffer. A worker callback
   after socket/stream cleanup still does not establish remote durable storage,
   thread return or release of all camera resources.
6. **Update validation:** one library caller passes zero to a validator's optional
   CRC argument. This is a bounded call-path observation, not a conclusion about
   the complete update authentication or boot verification chain.

## Reproduction and next work

The source bytes and readback checks remain the RUN002 baseline. Input manifests,
Ghidra commands, heap/CPU/time/response limits and export hashes are preserved in
each run directory and tracked survey manifests. New stage and symbol commands
are documented in `RUN003_REPRODUCTION.md`. Full catalogs, boot traces, complete
exports and unlocked project snapshots are linked by `manifests/drive-artifacts-run003.json`.

Next trace the readiness byte producer in the non-ELF/driver code, IPCC ioctl
handlers and message acknowledgements, HEVC/M4 configuration consumers, power
service listener, transfer callback consumers and the complete updater verification
chain. Function-level completion criteria and ABI/caller validation remain necessary;
the automatic survey and symbol catalog do not close these tasks.
