## New connections

1. **File-worker callback binding:** the inspected SaveExif route registers
   `SIFListener` through `DscImage` and `JpegDoneEx`, carries callback parameters
   through the JPEG worker's file-operation record, and reaches the file-worker
   callback previously reviewed in RUN004. That callback schedules
   `captureSaveDone` with `g_idle_add`. This supplies a concrete intended
   static binding; dynamic callback replacement and runtime ordering remain open.
2. **Queued status and write result are separate:** the inspected capture route
   queues zero before calling SaveExifImage. A separate exception route queues
   its error argument. The worker's constant callback arguments are notification
   arguments, not a checked `fwrite`/`fclose` result. The complete queue producer
   and failure-path limits are documented in the storage report; no global claim
   about every writer or error source is made.
3. **App registration and accounting:** original instructions bind the actual
   app callback for notification types 2 and 1. The app preserves status values
   1..12, maps other values to zero and routes converted 1..6 to error handling.
   Both normal and error accounting decrement the file count; the error-display
   latch does not prevent that decrement. A count of zero therefore cannot alone
   certify successful saving. BT content handling has separate path/existence/
   metadata gates and receives no storage-status argument at this inspected call.
4. **RTOS publication:** after writing the ready flag, the inspected routine
   supplies event `0x01010006` to a gated local publisher. A matching/wildcard
   subscriber list invokes observer vtable slot `+8` without checking its return.
   The actual transport-frame serializer, subscriber binding and Linux receiver
   correspondence remain unjoined. Local dispatch does not prove acknowledgement.
