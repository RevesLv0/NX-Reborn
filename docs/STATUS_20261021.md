함수 집계에는 thunk·컴파일러 보조 함수가, 문자열 집계에는 섹션 메타데이터가 포함된다.
이 수치는 기능 수나 전체 분석 완료율이 아니다. 비실행 메타데이터에는 ELF 실행 주소를 부여하지 않는다.

## 새로 재현한 중요한 사실

- `DscOsalFile::close` 내부에는 fclose 반환값에 대한 분기가 없다. 다만 반환 레지스터 r0는
  남아 있으므로 모든 외부 호출자가 무시한다고 일반화하지 않는다.
- 실제 writer 경로는 소멸자로 close를 호출하고, 별도로 저장한 쓰기 결과를 반환한다.
  이 경로에서 close 결과가 writer의 성공 판정에 포함되지 않는 것을 독립 확인했다.
- `DscFileHandler::taskMain`은 쓰기 결과를 검사하지만 성공·실패가 합류한 뒤 같은
  `(image, 0, 0)` 인자로 선택적 콜백을 호출한다. 해당 콜백만으로 파일 정상 저장을 보장할 수 없다.
- Ghidra의 공유 라이브러리 주소와 원래 ELF 주소에 +0x10000 차이가 있어 두 주소 체계를
  명시적으로 기록했다. di-camera-app은 원래 ELF 기준 주소 0x8000을 유지한다.
- UPnP XML의 ContentDirectory 액션 12개를 재확인했지만, 실제 장치에서 공개되는
  서비스·인증·원본 파일 URL은 여전히 실증되지 않았다.

상세 근거: `analysis/evidence/STORAGE_CROSSCHECK.md`,
`analysis/architecture/INITIAL_FINDINGS.md`, `analysis/architecture/WHOLE_FIRMWARE_MAP.md`.

## 남은 차단과 재개 절차

원본 ZIP 281,999,904바이트는 Drive fetch의 256MiB 한도를 초과한다. 기존 섹션 분할본은
사용 가능하지만 대용량 스트리밍 호스트가 현재 실행 세션의 정책에서 차단되어 있다.
사용자는 인터넷 액세스의 추가 허용 도메인에 주소를 추가했다고 확인했다. 이 실행 환경의
실제 정책에는 아직 없으므로, 설정 반영을 확인한 새 환경에서 다운로드를 재시도해야 한다.

1. 분석 브랜치를 복원하고 `python tools/bootstrap_research.py --work .work` 실행.
2. `/etc/codex/network-policy.json`에서 `sdmntprkoreacentral.oaiusercontent.com` 반영 확인.
3. Drive의 기존 분할본을 새로 fetch해 받은 인증 참조로 다운로드하고, 매니페스트의 순서·크기·해시 대조.
4. 전체 SLP 섹션·파일시스템을 재구성하고 기존 해시와 독립 비교. 그 전에는 전체 원본 재검증 완료로 표시하지 않음.
5. 전체 파일 인덱스 갱신 → 부팅/서비스/IPC·커널/드라이버·모든 실행 파일 의존성 추적.
6. 구조 지도의 기능별 목록에 따라 촬영/AF·이미지·영상·저장·통신·UI·전력·업데이트 분석을 확장.

복원 가능한 Ghidra DB 스냅샷과 분석 출력은 분석 실행 종료 후 저장한다. 전체 소스를 확보하지
못한 현재 상태에서도 위 결과는 보존·재사용할 수 있다. 카메라 접속·촬영·설치·플래시는 수행하지 않았다.
